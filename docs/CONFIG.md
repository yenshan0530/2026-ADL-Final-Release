# Config reference

Every option of the run files, models file and agent files, with its default. Generated by `python scripts/make_config_doc.py` from the config classes, so it matches the code; descriptions are the code comments. A field not given in a YAML file takes the default shown. The sample files in `configs/` override some defaults (e.g. configs/economy.yaml uses the fixed item spec).

## configs/economy.yaml (run_economy.py)

| `models` | list[str] | `['configs/models.yaml']` | Model registry file(s), merged in order (configs/models.yaml). |

## economy.yaml: grading

Grades for phases 1 and 2 from TA anchors (with `ta_anchors: true`).

<details><summary>notes from the code</summary>

```
Grades from TA anchors (phases 1 and 2). Per economy, the TA agents of the graded
role are ranked by mean raw score (seller profit, buyer surplus); the TA at
`low_percentile` gets `low_score` and the TA at `high_percentile` gets `high_score`
(position floor(p/100 x (n - 1)) from the lowest: with few TAs, the lower-scoring one,
which favors students). A student's grade is the straight line through the two
anchors at its raw score, not capped; its final grade is the mean over economies.
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `low_percentile` | float | `10` |  |
| `low_score` | float | `0.15` |  |
| `high_percentile` | float | `80` |  |
| `high_score` | float | `0.85` |  |

## market.rounds

<details><summary>notes from the code</summary>

```
Market length: every market lasts exactly `total` rounds of `turns_per_round` turns,
and agents are told `total`.

free_messages: per turn, up to this many successful messages (send_message /
post_to_room) do not use the turn: the agent acts again in the same turn. 0 = off.

The random length (min, max, continue_prob) was removed. Old configs with a fixed
length (min == max, or continue_prob 0) still load as `total`; others are refused.
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `total` | int | `5` |  |
| `turns_per_round` | int | `6` | Turns per round; every agent acts once per turn. |
| `free_messages` | int | `0` | per turn, up to this many successful messages (send_message / |
| `output_tokens_per_round` | Optional[int] | `8192` | Output tokens (visible + thinking) each LLM agent may generate per round, over all its calls. A call may use at most what is left (a longer reply is cut off there, as at max_tokens); with nothing left the agent waits until the next round. None: no limit. |

## market.schema

What an economy is played over: its items, drawn from the item price spec `items` (required), their kinds and prices.

<details><summary>notes from the code</summary>

```
What one economy (or one run_market repeat) is played over: its items, their kinds
and prices, all from the item file; nothing is drawn at random. Every market of the
economy plays the same items, so the whole class faces the same problem.

Every buyer values one unit of each item at its buyer value (more units are worth nothing,
but may be bought); an item's
units for sale = its kind's supply_ratio x buyers in the market.
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `kinds` | dict[str, KindSpec] | (see below: monopoly, oligopoly, scarce, competitive, balanced) | Item kinds: who sells an item and how much of it there is (see market.schema.kinds); which items have which kind: the item file. |
| `quality` | QualitySpec | (see its section) | Rules for items that can be delivered in a low grade (see market.schema.quality). |
| `items` | Union[str, list[str], None] | `None` | Item file (required): every item's seller cost and buyer value; the economy plays the items that have a `kind` (low_grade: true for items that can be delivered in a low grade). One file for every economy, or a list with one file per economy, exactly as many as `repeats` (e.g. [items_1.json, items_2.json, items_3.json] for 3 economies). |
| `budget_extra` | float | `0.15` | Each buyer's cash = (1 + budget_extra) x sum over all units for sale of mean(seller cost, buyer value), / number of buyers in the market. |

## market.schema.kinds.<name>

<details><summary>notes from the code</summary>

```
One kind of item. Which items have it is set in the item file (each item's `kind`).

supply_ratio: units for sale / buyers in the market (each buyer wants one unit;
              > 1: sellers compete; < 1: buyers compete for scarce stock).
sellers:      "all" sellers stock it, "one" (a monopoly), or how many do (3 = an oligopoly of three).
              A market with no more sellers than that gives it to all of them. Items
              sold by some sellers are dealt to the seller seats in item-file order, as
              evenly as possible: 5 monopoly items give 5 sellers one each, and 3
              sellers 2, 2 and 1 (rotation evens that out).
max_share:    with a number of `sellers`: at most this share of the market's sellers,
              rounded up, hold each item. Oligopoly {sellers: 3, max_share: 0.5}: 3 of 5
              sellers, 2 of 3, 1 of 2.
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `supply_ratio` | float | **required** | units for sale / buyers in the market (each buyer wants one unit; > 1: sellers compete; < 1: buyers compete for scarce stock). |
| `sellers` | Union[Literal['all', 'one'], int > 0] | `'all'` | "all" sellers stock it, "one" (a monopoly), or how many do (3 = an oligopoly of three). A market with no more sellers than that gives it to all of them. Items sold by some sellers are dealt to the seller seats in item-file order, as evenly as possible: 5 monopoly items give 5 sellers one each, and 3 sellers 2, 2 and 1 (rotation evens that out). |
| `max_share` | Optional[float] | `None` | with a number of `sellers`: at most this share of the market's sellers, rounded up, hold each item. Oligopoly {sellers: 3, max_share: 0.5}: 3 of 5 sellers, 2 of 3, 1 of 2. |

## market.schema.quality

<details><summary>notes from the code</summary>

```
Items a seller can deliver in a high or a low grade (`low_grade: true` in the item
file). The seller chooses the grade (hidden from the buyer) when listing or offering;
the buyer learns it on delivery.

low_utility: a low-grade unit's utility, x the high-grade utility of that unit.
low_cost:    a low-grade unit's cost to the seller, x the high-grade cost.
certification: sellers may mark a listing/offer "certified high"; the engine only
               allows it on high-grade units, so it is a credible signal.
reviews:     buyers may review a purchase (post_review); reviews are public.
disclosure:  "private": only the buyer learns the grade; "public": every agent is told.
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `low_utility` | float | `0.4` | a low-grade unit's utility, x the high-grade utility of that unit. |
| `low_cost` | float | `0.5` | a low-grade unit's cost to the seller, x the high-grade cost. |
| `certification` | bool | `False` | sellers may mark a listing/offer "certified high"; the engine only allows it on high-grade units, so it is a credible signal. |
| `reviews` | bool | `True` | buyers may review a purchase (post_review); reviews are public. |
| `disclosure` | Literal['private', 'public'] | `'private'` | "private": only the buyer learns the grade; "public": every agent is told. |

## configs/models.yaml: serving.<name>

<details><summary>notes from the code</summary>

```
How to run a registry model on local GPUs with vLLM: one server ("replica") per
entry of `gpus`, each holding the base model once. LoRA adapters are registered at
runtime and shared: vLLM keeps up to `max_loras` on the GPU, mixes requests for
different adapters in one batch, and swaps from a CPU cache of `max_cpu_loras`.

gpus: [0, 1, 2]   three replicas, one GPU each
gpus: ["0,1"]     one replica with tensor parallelism over GPUs 0 and 1
```

</details>

| option | type | default | meaning |
|---|---|---|---|
| `gpus` | list[int or str] | `[0]` | One replica per entry, e.g. [0, 1]; "0,1" = one replica over 2 GPUs. |
| `host` | str | `'localhost'` | Address the vLLM servers listen on. |
| `port` | int | `8000` | replica i listens on port + i |
| `max_loras` | int | `8` | LoRA adapters on the GPU at once (per batch). |
| `max_cpu_loras` | int | `64` | Adapters cached in CPU RAM; others reload from disk. |
| `max_lora_rank` | int | `64` | Largest LoRA rank the server accepts: 64 for the TA agents' LoRAs; students' are at most 32. |
| `gpu_memory_utilization` | float | `0.85` | Share of each GPU vLLM may use. |
| `max_model_len` | int | `64000` | prompt (system + history, up to ~20k tokens) + reply (max_tokens) |
| `tool_call_parser` | str | `'hermes'` | vLLM tool-call parser (Qwen3.5: qwen3_coder; Qwen3 instruct: hermes). |
| `command` | list[str] | `['vllm', 'serve']` | How to start vLLM. |
| `extra_args` | list[str] | `[]` | More `vllm serve` arguments. |
| `startup_timeout` | float | `900.0` | Seconds to wait for a server to come up. |
